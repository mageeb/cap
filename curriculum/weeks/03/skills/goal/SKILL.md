# Goal

Create a clear finish line before writing a full specification.

## Procedure

1. Define the **problem** being solved.
2. State the **user/developer outcome** in one paragraph.
3. Write 3–7 **observable success criteria**.
4. List **non-goals** that prevent scope expansion.
5. Capture hard **constraints**: compatibility, dependencies, performance, security, accessibility, data model, or repository conventions.
6. Remove implementation details unless they are genuine constraints.
7. Flag ambiguity instead of silently deciding product behavior.

## Output

Use this structure:

```markdown
# Goal: <name>
## Problem
## Outcome
## Success criteria
## Non-goals
## Constraints
## Open questions
```
